# Local transcription model review

Reviewed 24 October 2026 against current primary model cards, runtime documentation, and this app's code. This is a research and integration assessment, not a benchmark on the user's machine. Quality and speed judgements below are provisional. Target: Windows, CPU/Intel integrated GPU, local interview answers and imported recordings, readable timing and pause context, few recurring steps.

## Recommendation

Add Parakeet TDT 0.6B v3 as the first non-Whisper engine. Keep Whisper and expose Large v3 Turbo as the inexpensive integration baseline. Evaluate Granite Speech 4.1 2B Plus next when richer interview metadata matters; compare Qwen3-ASR when broader language coverage or difficult speech matters. Benchmark Granite 5.0 TurboCTC as a promising fast text recognizer, but do not promise timestamps or the newest multilingual checkpoint through an older conversion.

The goal is a small, tested catalog with meaningful choices, rather than exposing every downloadable checkpoint. Preserve the existing Record → Stop → Copy workflow across engines.

## Interpreting quality evidence

Cohere's model card records a March 26, 2026 English benchmark snapshot: average WER 5.42 for Cohere, 5.63 for Canary-Qwen, 5.76 for Qwen3-ASR 1.7B, and 7.44 for Whisper Large v3. These support testing alternatives; they are not a current universal ranking, a prediction of this user's correction burden, or a comparison of our packaged quantized engines. IBM's October 21 Granite 5.0 update reports 5.51 average English WER, with the new result described as unofficial and the leaderboard entry still representing the earlier checkpoint. Different dates and benchmark configurations prevent a simple merged league table.

For this app, preserve hesitations, names, technical terms and the relationship between words and long pauses. WER alone does not measure punctuation, lost repetitions, silence hallucinations or faithful timing. Keep recognition text and independent speech detection separate; a detector disagreement should remain visible rather than silently deleting recognized words.

## Runtime and existing code

The current `WhisperService` owns model downloads, FFmpeg normalization, inference, quiet detection and Silero speech detection. `TranscriptionService` manages jobs around it. `TranscriptionResult` is mostly reusable, but its timing-method union and renderer descriptions are Whisper-specific. The whitelist, model filename assumptions and frontend catalog also assume only tiny/base/small/medium/large. Those displayed MB values resemble parameter counts rather than the actual GGML download sizes and should be replaced with artifact sizes.

The bundled whisper.cpp source already includes `WHISPER_AHEADS_LARGE_V3_TURBO` and the CLI preset `large.v3.turbo`. The app currently allows alignment only for tiny/base/small/medium. Turbo therefore requires explicit manifest and preset changes, not a new engine or a parser rewrite. Validate the shipped executable as well as the checked-out source.

[transcribe.cpp](https://github.com/handy-computer/transcribe.cpp) is a particularly relevant runtime spike: native CLI/C API, Windows build guidance, CPU/Vulkan and multiple families. Its latest release inspected was v0.4.1, published October 22. Start with a pinned build and model revision, not a floating main checkout. Keep whisper.cpp as the established fallback until timestamp output, long recordings and packaging are verified. Runtime/model capability differences are explicit in its [Parakeet](https://github.com/handy-computer/transcribe.cpp/blob/main/docs/models/parakeet.md), [Granite](https://github.com/handy-computer/transcribe.cpp/blob/main/docs/models/granite-speech.md) and [TurboCTC](https://github.com/handy-computer/transcribe.cpp/blob/main/docs/models/granite-speech-5.0-turboctc.md) documentation.

[sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) is the other strong option, with [documented Parakeet conversions](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/offline-transducer/nemo-transducer-models.html). Distinguish its single-threaded Node WebAssembly examples from the multithreaded native Node addon. A small native helper process avoids tying our Electron build to a native Node module ABI and resembles our existing spawn-based integration. Neither ONNX nor a model's NVIDIA origin guarantees acceleration on Intel; test the exact execution provider. Avoid bundling Python/NeMo simply to make the first integration work.

## Implementation path

1. Introduce an engine interface behind the current job service. Keep FFmpeg conversion and speech-activity metadata shared. Initially retain the existing VAD binary even when recognition uses another engine.
2. Replace the five-name catalog with a curated manifest: stable model ID, engine, pinned revision, files/bytes/checksums, languages, quantization, license attribution, timing support, chunk limits and tested hardware providers. Preserve validated IDs and controlled download paths.
3. Normalize results into text, timed segments/words where available, language, model/engine provenance and a neutral timing method. Preserve original output for diagnostics. Never invent word timings by evenly distributing a text-only transcript across the audio.
4. Add Parakeet and Turbo behind the same existing workflow. For chunked engines, retain recording-relative offsets across silent regions; do not concatenate VAD speech chunks into a shorter timeline without mapping them back.
5. Benchmark before labelling a new recommended default. Keep the selection understandable: a few tested choices with actual download sizes and capability notes. Unsupported translation/language/timing features must not appear to work.

## Practical comparison before shipping

Use one consented local corpus across engines: short answers, a 5–10 minute interview answer, technical names/paths, hesitations and corrections, children or another speaker where appropriate, room noise, and repeated 20–30 second pauses. Include file import and repeated recording cycles. Manually transcribe a representative subset.

Measure cold model load, warm inference, stop-to-copy latency including conversion/VAD/alignment, peak memory, download size, correction burden/WER, omitted/repeated speech and invented words during silence. Record exact model revision, quantization, runtime commit, CPU/GPU provider and thread count. Compare CPU and Intel Vulkan where supported; do not use A100 throughput or Apple Metal results as a Windows prediction. A persistent worker may improve repeated-use latency but increases resident memory: measure both.

Verify timed text before/after long pauses against actual audio, without requiring perfect boundaries. For models lacking timings, either add a tested local aligner or explicitly offer plain-text capability; do not let adding choice regress the interview workflow. Run with models installed and networking blocked, and separately inspect connected operation. No new models were installed or benchmarked for this review.

## First implementation and qualification

Implemented subsequently on `codex/model-engines`, leaving `checkpoint/before-model-expansion-2026-10-24` at `03a374c` intact. Added the engine interface, curated manifest and verified staged downloads, Whisper Turbo Q5 and Parakeet v3 Q8. Existing Whisper recognition and independent Silero detection remain available. This is a limited functional qualification, not the comparative accuracy study proposed above.

Built transcribe.cpp v0.4.1 with the checked-in token-JSON adapter and tested Windows x64 / Intel Iris Xe Vulkan. The stock CLI exposes broad segments even when token timing is requested; the adapter exports actual token rows through the public API. A real microphone smoke test exposed delayed punctuation inside silence; the parser now attaches closing punctuation without extending speech duration, mirroring the existing Whisper handling and preserving all words.

Both new models pass the complete isolated offline microphone workflow with a synthetic 30-second pause, timestamped copy, file import, repeat/discard and stable controls. On the public 11-second JFK sample, Parakeet's first observed encode/decode took about 4.8 seconds plus 1.3 seconds model loading; a subsequent run took about 0.67 seconds encode/decode plus 1.0 seconds loading. Shader/cache warmup matters. These small-sample observations are not a throughput benchmark or a speed comparison with Whisper.

Validation: 101 frontend tests and 24 Electron tests pass; 48 renderer states show no page-wide overflow or readable text below 14px; 45 sampled pairings pass klar 3.1.0. Inspected three rendered passes, including new model rows, dark/light, narrow layouts and an unavailable-runtime build. Existing bundle/style warnings remain. Other OS/hardware, long interviews and representative accuracy remain unqualified. Neither new choice replaces the default based on this evidence. See [model setup and usage](models.md).
