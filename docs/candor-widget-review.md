# Candor widget inventory

Current app construction: **TalaTrace 1.2.0**, audited against the checked-in templates/styles on 26 October 2026. The app pins Candor tokens/web components to 6.0.0. This is an implementation inventory, not a fresh review of every current upstream story or an accessibility certification. Before changing a widget, follow [AGENTS.md](../AGENTS.md): read its current Storybook documentation and construction source again.

The [original construction/review log](archive/candor-widget-review-2026-10.md) preserves the iterations, sampled contrast results and deliberate decisions. Earlier approaches in that log are superseded by this inventory.

## Deliberate adaptations to preserve

- The settings modal adds an app key handler at its Tab/Shift-Tab edge to keep focus cycling through the actual Candor close/Done controls. Very short dialogs use supported spacing/heading variables so Done remains reachable. Do not hide focus outlines or replace the modal with a local imitation.
- Workflow cards preserve numbered sequencing, stable action positions, whole-second live duration and millisecond final duration. A new/failed/complete recording changes labels and availability rather than replacing the three action locations. The transcript heading is inside its card; settings belong in the footer-triggered modal.
- Dense actions and mono timestamps use 14px bold; reading prose/instructions remain at least 16px. Timestamp boldness is part of its measured contrast pairing. Quiet-help typography follows Candor's hierarchy role, not a blanket regular-text contrast assumption. See AGENTS.md for the exact OKCA floors and nesting rules.
- Placeholder spectrum marks and the 16px caption share measured contrast in both themes. Caption colour derives from the semantic subtle-text token with a relative-OKLCH lightness cap at 0.62 to match the current neutral marks; this is an app adaptation against the current palette and needs remeasurement after token changes. Live bars occupy the same 68×24px geometry. Reduced motion uses discrete readings, and silence does not fabricate activity.
- Labelled action icons use Phosphor fill/bold by role, supporting metadata uses regular, and glyphs carry one weight class with aria-hidden. Gear/help masks use Phosphor assets with the visible text supplying the control name. Do not substitute arbitrary Unicode arrows/triangles or title tooltips.
- Candor's scrollbar helper is not publicly exported. The app reproduces its token construction in `frontend/src/styles/_scrollbars.scss`, withholding standard scrollbar-color in Chromium so the wider grab area works. The forced-colour thumb alone opts out of substitution while using CanvasText/Canvas exclusively. RTL geometry is implemented; do not claim it has a complete native RTL audit.
- Tables use page-heading names instead of visible repeated captions at the user's request. Header sorting and ghost row actions preserve native semantics. This adaptation does not make importing token CSS equivalent to using a Candor table component.

## Evidence and limits

### Development export follow-up

The export format is a short native select with an explicit `label`/`for` association, following the Select story/construction and the app's existing native-select adaptation. Four values (TXT/SRT/VTT/JSON) determine the subsequent native save dialog's extension and filter. Menu was considered against its story but not used: this is a bound field value, and the pinned menu lacks the trigger-disabled/ghost construction needed here. The field remains available to preset while the Save action uses the workflow's existing disabled reason. Values and label are 16px; caret uses control-border/focus tokens, while text uses semantic text tokens. On small screens, the label sits above a shared selector/Save row with wrapping allowed. Record/Stop/Copy positions remain stable.

Local Storybook Select/Menu/Button/Card source and typography contrast guidance were read before editing. The published Chromatic URLs could not be retrieved by the web tool. Render review includes the existing app at 150% scale, the first export row, its mobile refinement and Linux rendering/keyboard checks. Full-band fixtures fill all 14 bars across all 102 backing pixels of the 68px canvas at DPR 1.5 on Windows and Linux; no production spectrum change is justified by that result alone. Speech can leave high-frequency bands quiet. This is sampled visual/contrast evidence, not an accessibility conformance audit.

The final Linux fixture run generated 129 states and passed its layout/keyboard/state assertions after correcting asynchronous resize hit testing in the harness. Sampled screenshots were inspected for desktop, 360/480px layouts, light/dark, recording, full-band signal, long file names, format focus and zoom. Klar 3.1.0 measured the shared export label/value pairings at OKCA 12.9 dark and 11.9 light (16px regular); forced-colour black/white measured 20. The pre-existing extreme-zoom settings/navigation overflow remains recorded separately.

The final pre-release workflow preview covered 126 states, including desktop/360/480px, short windows, themes, focus, capture/processing/result/copy/failure/import, settings and native scrollbar dragging/keyboard checks. The detailed [historical log](archive/candor-widget-review-2026-10.md) records sampled Klar 3.1.0 pairings and screenshots inspected. The 240px effective-width navigation overflow fixture remains a known gap; this is not a complete accessibility or screen-reader audit.

The [documentation audit](../AUDIT_REPORT.md) changed no UI. It found that older interview-smoke revisions did not isolate startup correctly. The repaired harness asserts appData/userData/sessionData after main loads; use [Development](development.md#verify-changes) for current behavior. Historical verification claims remain tied to their original revisions.
